# KnitScape 网页端界面规范 v1（iOS 风格，浅色）

本文件是网页端界面改版的唯一依据。改版逐页进行：一个页面迁移后，它的根元素带 `data-ui="ios"`，新样式只在这个范围内生效；没有迁移的页面保持原样。第一个试点是面料纹理页（T6a-3c）。

## 1. 原则

1. 按用户要做的事排顺序：设定 → 计算 → 看图看数 → 调外观 → 导出。最常用的操作和最重要的结果放在首屏，1366×768 也不用滚动就能看到。
2. 点之前就知道后果。每个控件属于下面五类之一，用颜色表示：

   | 类别 | 含义 | 图标底色 | 标签底色 / 文字色 |
   |---|---|---|---|
   | 需重算 | 改了要重新计算（几十秒到几分钟） | `#C75F00` | `#FFF1DC` / `#8A4B00` |
   | 几秒更新 | 几秒内更新，不重新计算 | `#0066D6` | `#E6F0FC` / `#0058B8` |
   | 只换显示 | 不计算，只换显示内容 | `#7C7C82` | `#ECECF0` / `#3A3A3C` |
   | 生成文件 | 下载文件 | `#248A3D` | `#E3F6E8` / `#1B6B2F` |
   | 停止恢复 | 停止任务、恢复默认 | `#D70015` | `#FDE8E7` / `#A1170F` |

   同一分组里的控件必须同一类；分组标题右侧用标签写明这一类的后果（例如“改了要重新计算”“不重新计算 · 通常几秒”）。标签只写不随设置变化的事实；耗时随设置变化的（例如计算精度、贴图精度），写在按钮下方或脚注里，按当前设置显示。
3. 一个控件一个图标：图案说明它做什么，底色说明它属于哪一类（第 5 节）。不同功能不得共用图案。例外只有三种：同一参数的两个控件（毛羽三档和强度滑杆在同一行，共用一个图标）；同一功能的两个方向（横向重复、纵向重复）；同一类导航动作（“更多参数”“更多外观设置”都用滑杆图案，以底色区分）。图案相近、缩小后难以分辨的，视同共用。
4. 用用户的词：界面上不出现 OpenGL、fullScan、d_e、ρ、CONVERGED、NOT_APPLICABLE 之类的内部名称；需要时放进“技术详情”。单位写在数值旁边。
5. 常用的露在外面，少用的收进面板（“更多参数”“更多外观设置”“导出设置”）；收起的功能一项不删。
6. 状态就地显示：进度、提示显示在它影响的区域里（例如预览区），不另起一行。
7. 结果过期时不清空：输入改了以后，旧的图和数字保留、变淡并注明“修改前”，新结果到达后替换；这段时间里会用到旧结果的动作（导出）禁用。
8. 文字对比度不低于 4.5:1；控件可点区域不小于 28×28 px，主按钮高 50 px。

## 3. 组件（类名统一 `ios-` 前缀）

- **页面框架**：左侧设定栏宽 360 px（底色 `--ios-bg`，右侧 1 px 分隔线，内边距 18/20/24，纵向间距 16，可独立滚动）；右侧详情区（底色 `--ios-detail`，内边距 16/24，纵向间距 12）。窄于 1100 px 时上下排列。
- **分组列表 `ios-group` / `ios-row`**：白底圆角 12；行高至少 44 px，左右内边距 16；行内左边为“图标底块 + 名称”（间距 12），右边为数值（次要色）和可选的箭头 `›`、上下箭头 `⌃⌄`（菜单）、步进器。行间分隔线从第 56 px 开始（与名称左缘对齐）。可点的整行用 `<a>` 或 `<button>`。
- **分组标题 `ios-section-header`**：13/600 次要色，左右内边距 16；右侧放后果标签 `ios-tag`。**分组脚注 `ios-section-footer`**：12 px 次要色，写这一组的补充说明或不可用的原因。
- **分段控件 `ios-seg`**：底 `--ios-fill`，内边距 2，圆角 9；按钮高 28，选中块白底带阴影。可以在文字前放 15 px 小图（第 5 节第二张表）。选项超过 4 个时改用菜单行（`⌃⌄`）。语义上是单选组：容器 `role="radiogroup"` 加 `aria-label`，每个按钮 `role="radio"` 与 `aria-checked`，方向键可切换。
- **步进器 `ios-stepper`**：两个 36×28 的按钮“−”“+”，底 `--ios-fill`，圆角 8，中间 1 px 分隔线。
- **主按钮 `ios-btn-primary`**：整宽，高 50，圆角 12，`--ios-tint` 底白字 19/600，文字前放 18 px 图标；不可用时不透明度 0.45。停止类主按钮用 `--ios-c-stop-bg` 底、`--ios-c-stop-text` 字。
- **胶囊按钮 `ios-btn-capsule`**：高 34，圆角 17，左右内边距 14，14/600；颜色取所属类别的标签色（例如导出用 `file` 类）。仅图标时宽 34 并带 `aria-label`。
- **统计卡片 `ios-stat`**：底 `--ios-well`，圆角 12，内边距 10/12；标题 12 次要色，数值 22/600，单位 12 次要色。
- **预览区 `ios-well`**：圆角 14，底 `--ios-well`，内边距 16。浮层：
  - 进度卡片：白底圆角 16、宽 340，标题 + 已用秒数 + 4 px 进度条 + 分步列表（当前步用蓝色转圈图标，未开始用空心圆，完成用对勾）。进度条按步骤分段：已完成的段填满，当前段显示来回移动的条纹，不估算百分比（求解一步可能持续一分钟以上，不能看起来像卡住）；
  - 提示胶囊：顶部居中，白底圆角 20，左侧 8 px 圆点（蓝 = 正在更新，橙 = 结果过期，灰 = 已停止）；需要用户动作时，胶囊末尾放蓝字按钮（例如“重新合成”）；
  - 空状态：52 px 线框图标 + 20/600 标题 + 14 px 次要色说明；
  - 旧结果：不透明度 0.35。
- **面板 `ios-sheet`**：用原生 `<dialog>` 加 `showModal()`（自带焦点限制和 Esc 关闭），关闭后焦点回到触发它的控件。底 `--ios-bg`，圆角 14，顶栏 52 px（标题居中 16/600，右侧“完成”蓝字 16/600），内容为分组列表；顶部放所属类别的标签。宽 380～460，居中显示，遮罩（`::backdrop`）`rgba(0,0,0,.25)`；点“完成”、遮罩或按 Esc 关闭。面板里的修改立即生效，“完成”只是关闭。
- **状态行**：12～13 px 次要色，左侧 8 px 圆点（绿 = 完成，蓝 = 进行中，橙 = 过期，灰 = 未开始或已停止）；错误用 `--ios-error` 文字。

## 4. 文案规则

- 按钮用动词开头（“计算面料”“导出面料贴图”“换一组纤维”）；状态句子以句号结尾，带耗时时写“已用 x 秒”。
- 假设值统一写“假设值，未经实测”，每组只写一次。
- 不能用的选项照常显示为灰色，并在分组脚注写原因。
- 改版后的页面文字走 i18n（4 种语言）；T6a 期间面料纹理页沿用 T6a §3.12 的约定只写中文，在后续改版步骤中补 i18n。

## 6. 迁移方式

1. 新样式全部写在 `styles.css` 末尾的“iOS UI v1”一段，选择器都以 `[data-ui="ios"]` 开头；不改这一段以外的规则。
2. 页面逐个迁移：给页面根元素加 `data-ui="ios"`，按本规范重写该页面的结构与文案。顶栏（任务栏）和页面切换最后统一迁移。
3. 现有检查读取 `styles.css` 中的特定规则，迁移时不得放宽或删除断言；某页迁移后旧规则不再生效、需要调整检查时，先停下报告。
4. 全部页面迁移后，再删除旧主题段（“LIGHT QUARTZ WORKSPACE”）和不再使用的旧规则。
5. 每个迁移步骤在 main 推送后更新 `ui-preview` 分支，由架构师在浏览器中按场景核对并截图。
6. 每个页面迁移前，架构师先给出该页的效果图和静态参考稿（HTML + 截图，随任务书附件转交，不入仓库）；参考稿用于核对结构、尺寸和颜色，代码按本规范用 lit-html 和 `ios-` 类名重写，不照搬参考稿的写法。
