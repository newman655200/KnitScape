# C　开源项目复用建议

2026-11-18。**保留 KnitScape 的机器执行、Feed × Yarn 求解和渲染链。最有价值的外部参考是 smobj 对“同一根纱延续到哪里”和“哪个旧圈由下一针接住”的分别表示。** 两者可以在同一位置发生，只有前者应当连接为连续纱线。

## 按功能取舍

| 功能 | 从参考源码得到的结论 | KnitScape 的选择 |
|---|---|---|
| 排针与逐路执行 | smobj 的 knitout 转换面向带方向、针床和 carrier 的针织操作。桌面项目已有针型循环 × Cam 的纯函数和实包回归。 | **沿用现有实现。** 保留 Pattern、排针、Cam 与 Machine 的边界，圆机 Feed 周期继续由本项目解释。 |
| 有向拓扑、旧圈保持与释放 | research-knitscape 的 ProcessModel 和 YarnModel 已是当前接触节点和沿纱遍历的来源。smobj 的面边分别标记旧/新圈及同纱出入；tuck 保留已有圈并加入新纱，miss 推进 carrier，knit 消费针上旧圈并形成新圈。[接触节点](https://github.com/knitscape/knitscape/blob/7861fc5fc34c876fee604e6d627429053fd6b6c6/src/simulation/ProcessModel.js) · [操作转换](https://github.com/textiles-lab/smobj/blob/9be5384cb6b5500574a429968de0987ca4bd27bc/utilities/knitout-to-smobj.cpp#L1811) | **保留 CN；借鉴两种端口的语义。** 对现有 K–T–T–K 释放组，可分别核对旧圈归属和每根纱的有向路径，避免把共享接触点误连成同一根纱。 |
| 主纱、氨纶连续路径 | smobj 依面边连接及穿越次序拼接局部纱段，并用有序检查点判定链方向。平床 carrier 的往复与添纱顺序仍有适用条件。[纱链拼接与定向](https://github.com/textiles-lab/smobj/blob/9be5384cb6b5500574a429968de0987ca4bd27bc/utilities/sm.cpp#L3202) | **借鉴有向连接与来源标识；独立定义供纱关系。** 两纱分别保持身份。跨 Feed、跨行或主氨前后次序只能在有圆机和工艺证据时连接。 |
| 纱长与约束 | smobj 可给沿纱检查点之间附目标长度和单位。这个表示本身不决定区间内纱长如何分布。research-knitscape 的二维 D3 力布局也未提供逐路逐纱的 cm/100 针验收。[检查点格式](https://github.com/textiles-lab/smobj/blob/9be5384cb6b5500574a429968de0987ca4bd27bc/README.md#L46) · [二维布局](https://github.com/knitscape/knitscape/blob/7861fc5fc34c876fee604e6d627429053fd6b6c6/src/simulation/YarnForce.js) | **沿用求解器；借鉴有单位的测量区间。** 未来如果验收三维纱长，应以相同 Feed、纱、起止针和状态对齐目标与弧长。放松/织造态、直径和实际误差仍由本项目独立标定。 |
| 三维几何、外观与保存 | smobj 提供从纱折线到显示管面的实现；这条绘制链不能保证全布局满足有限半径间隙。两个参考项目均未给出针对当前双纱圆机的完整长度与接触求解方案。[管面绘制](https://github.com/textiles-lab/smobj/blob/9be5384cb6b5500574a429968de0987ca4bd27bc/web/renderers.tubes.js) | **沿用当前管面、PBR、预览与项目包。** 保留可追溯的几何审计。穿套方向、允许接触和禁止穿透的判据需要独立工艺依据；开发前先把观测定位到具体路径和管面。 |

本轮仅阅读两个参考工作区，无代码、模板或素材移植。
