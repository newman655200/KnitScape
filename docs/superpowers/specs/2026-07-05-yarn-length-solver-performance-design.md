# 纱长共享系数求解性能修复

## 问题

默认 `48 × 60` 普通成圈图在纱长为 `0.90` 时，一次同步预览重算实测约 `55.9s`，期间浏览器主线程无法响应。根因是当前实现对每一行执行五轮系数求解；每轮扫描并细化约一百个候选系数，每个候选又重新生成、解析和采样该行全部曲线。

## 目标

- 调整第一支纱线纱长时不再出现长时间未响应。
- 普通成圈行使用同一个共享形状系数，符合相同线圈只计算一次、后续直接复制的要求。
- `0.90`、`1.00`、`1.10` 的中心路径长度和紧致/蓬松方向保持正确。
- 相邻路径继续从共享节点生成，连续性容差仍为 `1e-6` 针距单位。
- 第二支及后续纱线继续直接复用第一支纱线的最终路径。

## 设计

### 一次求解

从支持普通成圈模型的行中选取一个代表行，优先使用非首尾的完整行。只在该行上计算基准长度并调用一次有界系数求解器，得到全局共享系数 `k`。所有支持的 knit / purl 行直接使用同一个 `k`；slip / tuck 或不支持行保持系数 `1`。

代表行只决定无量纲形状系数。最终每一行仍从自己的共享节点生成路径，并逐行执行连续性检查；失败行整行回退基准路径，不影响其他行。

### 缓存

按图案拓扑、第一支纱线直径和纱长比例缓存共享系数。相同输入再次出现时直接复用系数，不重复弧长搜索。缓存设置小容量上限，避免长期编辑过程中无限增长；图案或几何输入变化后自然使用不同键。

### 交互调度

保留滑块数值的即时状态更新，但把昂贵的预览重算防抖时间从 `30ms` 提高到适合拖动的短延迟。连续拖动只执行停止后的最后一次重算，不恢复“模拟”按钮。

## 验证

- 新增真实 `48 × 60` 普通成圈运行时测试；修复前必须复现明显超时，修复后单次求解应低于 `2s`。
- 自动验证大图只使用一个共享求解结果，`0.90` 与 `1.10` 路径均不同于基准。
- 保留总路径目标误差、多纱路径完全一致、连续性、slip / tuck 回退等现有验证。
- 浏览器连续拖动纱长滑块后页面保持响应，无控制台错误。
- 全部 `validate:*` 和生产构建通过。

## 非目标

- 本次不引入 Web Worker。
- 不改变纱长范围和线圈形状数学定义。
- 不扩展 slip / tuck 的纱长模型。
