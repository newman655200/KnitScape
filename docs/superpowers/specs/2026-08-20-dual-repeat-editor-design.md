# KnitScape 双循环单元编辑器设计

日期：2026-08-20

状态：已由用户确认，待实施

## 1. 背景

当前版本已经把三角座排列和排针排列拆成上下两个编辑器，并支持“开始排针”和四段输入转换。但当前编辑器直接把位图尺寸当成完整画布尺寸，导致上一版本的黑色循环单元、灰色平铺区域、局部视角缩放/拖拽和固定色纱栏消失；尺寸输入也被放到了两个编辑器标题行中。

本次设计恢复上一版本“循环单元生成完整画布”的核心能力，同时保留现在的双编辑器和排针转换。

## 2. 目标

1. 完整画布默认并统一为 `60×60`，横向针数和纵向针数放在顶部针法栏的“半针”之后。
2. 三角座和排针分别保存自己的循环单元；默认都为 `8×4`。
3. 黑色循环单元是唯一可编辑区域；灰色完整画布由循环单元自动平铺生成。
4. “开始排针”保持 `8×4` 深拷贝；输入 `1、2、3、4` 并成功应用后，排针循环单元变为 `4×8`，完整画布仍为 `60×60`。
5. 标准桌面布局下，上下编辑器初始视口都显示同一块 `16×16` 区域，并共享滚轮缩放和中键拖拽状态。
6. 两个编辑器都有固定在左侧的色纱栏，共享同一份完整画布行序列，并且永不覆盖灰色网格。
7. 恢复尺寸输入的键盘输入和原生上下箭头操作，编辑期间文字始终为黑色。

## 3. 非目标

- 不恢复旧版多重复块叠加、重复块移动、重复区域拖拽边框或重复块库。
- 不允许直接编辑灰色平铺结果。
- 不为上下编辑器建立独立缩放或独立平移。
- 不改变四种针法、排针输入校验规则、右侧纱线模拟算法或双纱参数。

## 4. 界面布局

### 4.1 顶部针法栏

顶部从左到右排列：

1. “针法”标题；
2. 成圈（下）、成圈（上）、平针、半针；
3. 横向针数；
4. 纵向针数。

横向和纵向输入默认均为 `60`，允许输入和使用原生步进按钮，提交范围为 `5–500`。输入框在普通、聚焦、选择文字和暂时无效状态下都使用黑色前景。

### 4.2 三角座排列

“三角座排列”标题下直接显示编辑视口。视口左侧是独立色纱栏，右侧是裁剪后的完整画布。标准桌面布局下，初始视角显示左上方 `16×16` 格；窗口不足时按可用空间缩小视口，但不主动显示超过 `16×16` 的范围。黑色 `8×4` 循环单元位于默认可见范围内，其他区域显示为灰色平铺结果。

### 4.3 排针排列

“排针排列”标题下先显示一整行排针控件：开始排针、排针输入 1、2、3、4、应用排针。控件下方是与三角座结构一致的固定色纱栏和编辑视口。

默认打开和点击“开始排针”后，排针黑色循环单元为 `8×4`；只有成功点击“应用排针”后，才按输入转换循环单元。输入 `1、2、3、4` 的结果为 `4×8`。

## 5. 数据模型

运行时保存以下核心状态：

```text
canvasWidth: number                // 默认 60
canvasHeight: number               // 默认 60
camUnitBitmap: Bimp                // 默认 8×4
needleUnitBitmap: Bimp             // 默认 8×4
needleInputs: [string, string, string, string]
appliedNeedleInputs: [string, string, string, string]
needleInputErrors: [errorOrNull, ...]
yarnSequence: Bimp(1, canvasHeight, yarnIndexes)
chartScale: number
chartPan: { x, y }
```

完整画布不作为第二份可变业务数据保存，而是由纯函数生成：

```text
camBitmap = tile(canvasWidth, canvasHeight, camUnitBitmap)
needleBitmap = tile(canvasWidth, canvasHeight, needleUnitBitmap)
```

这样可避免循环单元与灰色区域失配。右侧预览和所有针法导出读取完整的 `needleBitmap` 派生结果。

## 6. 数据流

### 6.1 新建与默认状态

- 完整画布为 `60×60`；
- 三角座循环单元为 `8×4`；
- 排针循环单元为三角座循环单元的深拷贝；
- 色纱序列为 60 行；
- 标准桌面布局下，默认视角对准左上方并精确显示 `16×16` 格。

### 6.2 编辑三角座或排针

左键绘制只在对应黑色循环单元内生效。绘制动作更新循环单元，然后重新派生完整平铺位图。灰色区域不接收绘制动作。

### 6.3 开始排针

“开始排针”把当时的 `camUnitBitmap` 深拷贝到 `needleUnitBitmap`。它不修改四个输入草稿、最近一次成功应用值或尚未解决的输入错误。

### 6.4 应用排针

应用前完整校验四个输入，只接受字符 `1–4`，并要求引用行存在于三角座循环单元。全部通过后才转换：

```text
needleUnit.pixel(n, x) = camUnit.pixel(x, input[n] - 1)
输出宽度 = 拼接后的输入长度
输出高度 = 三角座循环单元宽度
```

因此 `8×4 + 1234` 生成 `4×8` 排针循环单元。完整排针画布再由该单元平铺为当前完整画布尺寸。

### 6.5 修改完整画布尺寸

横向或纵向针数只更新 `canvasWidth / canvasHeight`，不裁剪或缩放两个循环单元。纵向针数变化时，色纱序列保留现有行并按当前活动色纱补齐新行。

如果循环单元大于完整画布，完整画布只取能够容纳的平铺部分，循环单元本身不丢失数据。

## 7. 编辑视口交互

上下编辑器共享 `chartScale` 和 `chartPan`：

- 鼠标滚轮以当前指针所在格附近为中心缩放；
- 鼠标中键拖动任一编辑器时，上下两个灰色画布同步移动；
- 缩放和平移只作用于右侧画布窗口；
- 两个色纱栏固定在各自编辑器左侧，不参与水平平移；
- 色纱栏按相同纵向缩放和平移与画布行保持对齐，并分别裁剪在各自视口内；
- 尺寸变化、缩放和拖拽都不得让色纱栏覆盖或进入灰色网格区域。

## 8. 色纱共享

`yarnSequence` 按完整画布行数保存，默认 60 行。上下两个色纱栏读取同一份 `yarnSequence`，并调用同一组色纱编辑动作。在任意一边修改某一行后，另一边相同行立即同步。

色纱选择不是循环单元的 4 行重复数据，也不因排针应用从 `8×4` 变为 `4×8` 而改变。只有完整画布纵向针数变化时才调整色纱序列高度。

## 9. 尺寸输入问题的根因与处理

当前全局键盘监听器在数字输入获得焦点时仍处理数字快捷键。键入尺寸会切换针法并派发状态更新，引发根视图重绘，干扰尚未提交的输入状态和视觉样式。

处理方式：

1. 键盘快捷键检测到目标是 `input`、`select`、`textarea` 或可编辑元素时直接退出；
2. 尺寸输入使用本地浏览器编辑状态，按回车或失焦后提交；
3. 原生上下箭头通过同一提交路径更新尺寸；
4. 为尺寸输入的普通、聚焦和选中状态显式设置黑色前景。

## 10. 文件格式与迁移

新导出格式升级为 JSON v3，明确保存完整画布尺寸、两个循环单元、排针输入和共享色纱数据。

迁移规则：

- 旧 repeat 格式：读取原循环单元和区域尺寸；三角座使用原循环单元，排针初始为其深拷贝；
- JSON v2：将保存的三角座位图和排针位图分别作为循环单元导入，完整画布采用 `60×60`，不裁剪现有针法数据；
- JSON v3：严格校验画布尺寸、循环单元尺寸、像素数量和四段输入；
- 导出只写 JSON v3。

## 11. 错误处理

- 任一排针输入无效时，只更新对应错误信息，不改变排针循环单元、完整平铺结果、右侧预览和已应用输入；
- 完整画布尺寸提交时规范到 `5–500`；编辑期间暂时为空不会立即写入状态；
- 缩放限制沿用现有最小和最大值；
- 灰色区域的左键事件不修改数据；
- 中键拖拽阻止浏览器自动滚动行为。

## 12. 验收标准

自动验证至少覆盖：

1. 新建项目完整画布为 `60×60`，两个循环单元均为 `8×4`；
2. 开始排针后仍为 `8×4` 深拷贝；
3. 应用 `1、2、3、4` 后排针循环单元为 `4×8`，完整画布仍为 `60×60`；
4. 灰色区域严格等于黑色循环单元的平铺结果且不可编辑；
5. 上下视角共享缩放和平移；
6. 两个固定色纱栏共享完整画布行数据，不与网格重叠；
7. 数字输入期间文字为黑色，且数字快捷键不触发；
8. JSON v3 往返以及 repeat/v2 迁移正确；
9. 右侧预览、SilverKnit、Kniterate 和打孔卡读取完整排针派生结果；
10. 现有多语言、双纱、纹理、纱长和撤销验证继续通过。

浏览器验收按用户提供的截图逐项检查布局、默认 `16×16` 视角、黑色循环单元、同步滚轮缩放、中键拖拽、固定色纱栏和尺寸输入行为。最后运行全部 `validate:*` 脚本与生产构建。
